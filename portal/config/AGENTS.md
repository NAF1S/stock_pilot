# portal/config — Configuration

Standard Laravel config files, read through `config('...')`. Never hardcode a value that belongs in `.env`.

## Files

- `stockpilot.php` — the only custom file. Single key: `webhook_mode` (`SP_WEBHOOK_MODE`, `sync` | `queue`),
  read by `WebhookController::dispatch()` to choose `ProcessWebhookEvent::dispatch()` (queued) versus
  `dispatchSync()` (inline).
- `app.php`, `auth.php`, `cache.php`, `database.php`, `filesystems.php`, `logging.php`, `mail.php`,
  `queue.php`, `sanctum.php`, `services.php`, `session.php` — framework defaults, configurable via `.env`.

## Environment variables that change behaviour

| Variable | Notes |
|---|---|
| `APP_KEY` | Auto-generated by `AppServiceProvider::ensureAppKey()` when missing or invalid |
| `APP_URL` / `APP_ENV` / `APP_DEBUG` | Production must run `APP_DEBUG=false` |
| `DB_CONNECTION` + `DB_*` | `.env.example` ships Supabase PostgreSQL; MySQL is the documented alternative, SQLite the fast local/testing option |
| `SESSION_DRIVER`, `SESSION_DOMAIN`, `SESSION_SECURE_COOKIE` | Cookie-session behaviour for the SPA |
| `SANCTUM_STATEFUL_DOMAINS` | Must include the portal domain, or SPA auth fails |
| `QUEUE_CONNECTION=database`, `CACHE_STORE=database` | No Redis required |
| `MAIL_MAILER` | `sendmail` by default; switch to `smtp` when the host blocks PHP mail |
| `SP_WEBHOOK_MODE` | `sync` (default, no worker) or `queue` |

`config/stockpilot.php` and the full variable table live in the root [README.md](../../README.md).

## Rules

- Config is cached in production (`php artisan config:cache`): after editing defaults or `.env`, run
  `php artisan config:clear` locally (or rebuild the cache on the server) or the change is ignored.
- `SetupService` rewrites the `DB_*` block of `.env` at runtime during the install wizard — keep those keys
  grouped and regex-compatible if you touch the wizard or the env template.
- Prefer reading config over `env()` outside config files; `env()` returns `null` once config is cached.
